Laboratory 4 – Final Detailed Design Reference

Architecture overview, 3NF/BCNF relational database schema, and security controls approved in the Lab 4 Consolidated Detailed Design Record (DDR).

1. FinPay Layered Software Architecture

1. ROUTER LAYER

Flask HTTP Endpoints

  • Validates TalentHub JWT token (signature, expiry, roles: student, finance).
  • Rejects invalid tokens with 401 Unauthorized.
  • Extracts student_id from token subject claim.
2. SERVICE LAYER

Business Logic & Limits

  • process_payment(): Orchestrates payment atomic flow.
  • calculate_cashback(): Pure floor DIV integer algorithm.
  • Ownership Check: wallet.student_id == token.sub (403 if mismatch).
  • Monthly Cap: Enforces calendar-month limits via SUM query.
3. REPOSITORY LAYER

Parameterized SQL

  • FinPayRepository handles parameterized queries.
  • Enforces PRAGMA foreign_keys = ON.
  • Index on (wallet_id, created_at) for fast monthly SUM.
4. DATABASE LAYER

SQLite (Option A: RDBMS Only)

  • Stores all money as whole integer paise.
  • Stores rates in basis points (rate_bps).
  • Guarantees ACID transactions with BEGIN IMMEDIATE.

2. Normalized Relational Schema (3NF & BCNF)

WALLET_TIER Lookup Table 
tier TEXT PRIMARY KEY
rate_mult_x10 INTEGER NOT NULL
cap_mult_x10  INTEGER NOT NULL

-- Fixed Data:
BASIC   (10, 10)  -- 1.0x
PRIME   (15, 15)  -- 1.5x
PREMIUM (20, 20)  -- 2.0x
CASHBACK_RULE Lookup Table 
category_code           TEXT PRIMARY KEY
rate_bps                INTEGER NOT NULL
basic_monthly_cap_paise INTEGER NOT NULL

-- Fixed Data:
CANTEEN    (200 bps = 2.0%, ₹50 cap)
STATIONERY (100 bps = 1.0%, ₹20 cap)
TRANSPORT  (300 bps = 3.0%, ₹100 cap)
HOSTEL     ( 50 bps = 0.5%, ₹200 cap)
ONLINE     (100 bps = 1.0%, ₹30 cap)
TOPUP      (  0 bps = 0.0%, ₹0 cap)
WALLET Entity Table 
wallet_id     INTEGER PRIMARY KEY AUTOINCREMENT
student_id    TEXT UNIQUE NOT NULL
tier          TEXT NOT NULL REFERENCES WALLET_TIER(tier)
balance_paise INTEGER NOT NULL CHECK(balance_paise >= 0)

-- /monthly_cashback is a derived attribute,
-- not stored to prevent stale-data anomalies.
MERCHANT Entity Table 
merchant_id   INTEGER PRIMARY KEY AUTOINCREMENT
merchant_name TEXT NOT NULL
category_code TEXT NOT NULL REFERENCES CASHBACK_RULE(category_code)
ON DELETE RESTRICT
TRANSACTION Transactional Audit Ledger 
transaction_id  INTEGER PRIMARY KEY AUTOINCREMENT
wallet_id       INTEGER NOT NULL REFERENCES WALLET(wallet_id) ON DELETE RESTRICT
merchant_id     INTEGER NOT NULL REFERENCES MERCHANT(merchant_id) ON DELETE RESTRICT
idempotency_key TEXT NOT NULL
amount_paise    INTEGER NOT NULL CHECK(amount_paise > 0)
cashback_paise  INTEGER NOT NULL CHECK(cashback_paise >= 0)
created_at      TEXT NOT NULL

CONSTRAINT unique_wallet_idemp UNIQUE(wallet_id, idempotency_key)
INDEX idx_trans_wallet_created ON TRANSACTION(wallet_id, created_at)

3. Key Security Controls Approved in DDR (Part C)

1. TalentHub JWT Authentication & Service Ownership Check (Control B):

JWT signature is verified in the router; the service layer checks wallet.student_id == token.subject. Prevents student A from making payments on student B's wallet.

2. Role-Based Field Filtering (Control A):

Each endpoint returns only the data authorized for the caller. Students see only their own wallet and transaction history; Finance officers see reconciliation aggregations.

3. Database-Level Idempotency Check (Control A):

Enforced by UNIQUE(wallet_id, idempotency_key). Re-submitting the exact same idempotency key returns the original transaction record without duplicate debits or cashback.
